# Telnet watchdog recovery checks

The functional script remains in `tutorials/setup-persistent-unauthenticated-telnet/replace_with_test.sh`. This directory holds development verification only.

Run `python3 test_watchdog.py` on Linux with Python 3 and gcc. It copies the production script into a private temporary directory, substitutes temporary paths and fake commands, and uses a one-second polling interval. A compiled fake `telnetd` opens no sockets. `netstat`, `iptables`, `start-stop-daemon` and `id -u` are intercepted. Actual host `/proc`, process termination, shell traps, lock handling and detached subprocesses remain in use. The host test does not verify real root credentials, stock BusyBox detachment behavior, actual packet filtering, live socket ownership or firmware boot order.

On 2026-11-05, all 15 integration checks passed: simultaneous invocations converged to one watchdog; SIGTERM/SIGKILL daemon recovery; firewall-rule restoration; stale daemon and watchdog PIDs referring to unrelated live processes; recovery of a managed process without a listener; occupied-port handling; failed-launch retry; and explicit stopping without automatic resurrection. The original ONT BusyBox also accepted the production script with `sh -n` under local qemu-aarch64 (exit0, fallback-suid notice). That syntax check did not execute the hook.

`results.json` retains the exact check list, production script hash and native syntax-check scope. No router was contacted or changed. A real reboot using the revised payload remains untested. Tests cannot establish which stock component terminated the old boot-time daemon; `killall telnetd` in stock stop_service remains a candidate, not an observed cause.

Final launcher detail: `start-stop-daemon -p /dev/null` (without `-m`) deliberately supplies an empty PID source, so starting `/bin/sh` is not suppressed by unrelated shell processes. Supervisor locking handles duplicate detection instead. Captured ONT BusyBox was also exercised locally with `start-stop-daemon -S -p /dev/null -x /bin/true`, exit0; this harmless command does not check background detachment or real credentials. The test launcher asserts this PID-source option and absence of `-m`.

Validation history: initial host checks passed. Review identified the missing PID-source guard in the launcher; this was corrected before deployment. During reruns the harness sampled a PID twice in one predicate, which could report a vanished child as a replacement and then attempt signalling PID0. The harness now samples once and asserts PID>1 before sending any signal. Interrupted host runs left local fixtures; only exact-match `/tmp/telnet-watchdog-test-*/hook.sh --root-telnet-watchdog` supervisors were terminated, which cleaned up their fake daemons. The corrected final run passed all15 checks. No router was involved in those failures.

Upstream behavior reference: [BusyBox1.34.1 start_stop_daemon.c](https://raw.githubusercontent.com/mirror/busybox/1_34_1/debianutils/start_stop_daemon.c), `do_pidfile` and `do_procinit`: a supplied PID file restricts matching to parsed PIDs rather than scanning every process. An empty readable file produces no matches. This supports the guard; vendor runtime checks remain separately scoped above.
